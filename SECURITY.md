# Security Policy

## Supported Versions
Only the default branch (or latest release) is actively supported.

| Version / Branch | Security Support |
|------------------|------------------|
| Default branch   | ✅ Yes            |
| Older releases   | ❌ No             |

---

## Security Principles
This repository:
- Does not contain secrets, credentials, or sensitive configuration
- Is designed to be safe for public disclosure
- Follows secure‑by‑design principles aligned to NCSC guidance

Contributors must avoid introducing dependencies or configuration that weaken security posture.

---

## Reporting a Vulnerability
If you believe you have discovered a security vulnerability:

**Please do not raise it via a public GitHub issue.**

Instead:
- Contact the maintainers via: **[DORS Operations Email Address]**
- Clearly describe the vulnerability, affected files, and potential impact

We aim to acknowledge reports in a reasonable timeframe, but response times are not guaranteed.

---

## Disclosure Process
- Confirmed vulnerabilities will be assessed by the maintainers
- Fixes may be released at the maintainers’ discretion
- Public disclosure will be handled responsibly and proportionately

---

## Prohibited Submissions
The following must never be submitted via issues or pull requests:
- Credentials, secrets, or tokens
- Personal data (real, test, or synthetic that resembles real individuals)
- Details of live government infrastructure
- Exploitable security details unrelated to this open‑source codebase

Such submissions may be removed without notice.

---

## Security Review
This repository may be subject to:
- Internal UK Government security review
- Automated dependency and secret scanning
- Independent review via public contribution
